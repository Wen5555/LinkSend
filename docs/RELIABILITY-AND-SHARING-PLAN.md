## 1. 目标与范围

以现有 Windows/macOS 桌面端为基础，完成连接与恢复、跨网络直连、文件剪贴板完整使用链路、可操作诊断、安装升级与退出一致性；新增程序自动管理的剪贴板文件缓存和一次性临时分享，同时收敛文档、模块职责与交付流程。

本计划接受用户2026-10-19的范围调整：缓存由程序自动管理，不让用户选择容量、保留期限或手动清理；一次性临时分享纳入本轮必做；保存常用发送方案暂不做。允许使用SSH连接相关服务器和Mac，在阶段完成后及时提交并推送GitHub。

2026-10-26 用户进一步明确可用 Linux 服务器替代 Mac，不再等待 Mac：连接、双向传输、恢复和一次性临时分享采用 Windows↔Linux 实网验证。此调整不把 Linux 的结果写成 Finder、DMG 或 macOS 原生通过；Windows Explorer 实际键盘粘贴、自动缓存和 Windows 安装退出旅程继续实施，Mac 专属证据保留未验证边界。

计划编写阶段仅交付文档。2026-10-19 用户随后明确发送启动指令，本轮进入实施并授权相关 SSH 及已验证增量的 commit/push；不恢复旧 Goal、旧代理、远程作业或 heartbeat，生产与宿主网络边界仍按下文执行。

## 4. R1 连接 恢复与跨网络直连

### 行为要求

- 同LAN的发现、双方同意、独立配对与双向传输，在信令/STUN不可用时仍可工作。通过专用profile或测试注入模拟外部服务不可达，不修改宿主防火墙、路由或代理。
- 修复有证据的双端同时连接、过期地址、网络切换、睡眠唤醒、重连状态残留问题；连接尝试有期限、退避、取消及代次隔离，不堆积worker。
- 发现刷新或信令短断不取消健康QUIC连接。实际路径失效后重新认证、恢复原任务，不重传已确认内容，不绕过源变化确认。
- 保留暂停、取消、撤权优先级；晚到回调不能恢复已取消任务。离线期间的旧剪贴板内容不因重连补发。
- 跨NAT分开检查HTTPS/WSS、外部STUN、ICE候选与检查、QUIC认证、文件校验。STUN响应不能单独证明NAT类型或可打洞。

### 必要验证

先复现具体故障并添加定向回归，再完成Windows↔Mac两方向各一次包含小文件、较大文件、中文路径和空目录的真实传输与hash校验。复用同一旅程覆盖必要的中断恢复、一次原生睡眠唤醒或网络切换；只操作隔离任务和明确受管资源。

跨网至少完成一组实际不同网络、无需测试专用固定端口映射的双向认证文件传输，记录两端拓扑和真实结果。受控双NAT、固定映射、同桥、loopback各自标明，不能互相替代。若只有受限网络无法直连，给出失败阶段及环境证据，不承诺100%成功，也不私自加入中继/TCP文件替代方案。

完成条件：已定位产品缺陷修复，LAN关键旅程通过；真实跨网成功范围明确。缺乏可用双端网络条件时，跨网仍为`BLOCKED_BY_EXTERNAL_ENV`，本Goal不能据此整体标完成。

## 5. R2 文件粘贴与全自动缓存

### 5.1 文件粘贴闭环

Windows复制文件 → Mac通过Finder实际Cmd+V粘贴，以及Mac复制 → Windows通过Explorer实际Ctrl+V粘贴，均核对落地集合、内容hash和目录结构。原生剪贴板文件条目读回不能替代键盘粘贴。

沿用文件独立双端授权和大文件居中进度；覆盖连续复制取最新、传输取消、目录/多文件、同名目标、源变化和失败后的再次复制。失败不发布部分文件；不得把“剪切”传播为删除源文件。应用重启不补发旧复制。

### 5.2 用户体验

缓存的容量预算、保留时间、回收触发和失败重试由程序负责。不给用户增加缓存设置页、清理按钮、期限选择或清理确认对话框，也不把“请用户手动删缓存”作为正常解决路径。

正常回收静默完成。确实无法接收新文件时，用简短提示解释空间不足或文件仍在使用；不得反复弹窗。诊断可展示只读占用与受保护数量，不让用户决定删除对象。

### 5.3 所有权与自动回收

| 状态 | 程序处理规则 |
|---|---|
| 正在接收、校验、提交或发布到剪贴板 | 强制保护；生命周期owner持有引用；清理不能竞争删除 |
| 当前系统剪贴板仍引用文件 | 保留可用路径；新版本或重启后的程序须重新核对，不按年龄删除 |
| 已不在当前剪贴板，但可能正被Explorer/Finder复制 | 进入保守保护期；不能把剪贴板变化视为系统粘贴已经完成 |
| 已结束且无引用、满足安全回收条件 | 按自动TTL或空间压力回收，删除前再次复核代次、引用和所有权 |
| 失败或取消且从未发布的临时文件 | owner退出并关闭句柄后自动回收；失败有界重试 |
| 崩溃遗留、旧版本或元数据不完整 | 启动时有界对账；所有权可证明才纳入管理，不按目录名猜测可删 |

实现前写缓存ADR，冻结状态转移、持久元数据、崩溃一致性、文件引用与原生适配边界。复用既有Go/profile存储owner，不增加第二个并行数据库owner。

工程初始策略可采用“无引用后至少24小时保护、正常7天回收、空间压力下仅提前回收已满足保护条件的对象”；这些是待平台核验的实现参数，不是用户设置，也不是粘贴结束的证明。若平台不能可靠判断仍在读取，必须通过受控原生交接或进一步保守保留解决，不能仅凭TTL强删。第三方剪贴板历史无限期保留路径不属于本轮承诺，需在技术边界中说明。

回收在启动对账、任务结束、剪贴板变更、空闲周期及空间压力时触发；单轮目录数、I/O预算、扫描频率和重试次数有上限。禁止频繁递归扫描整个用户目录。

接收前对所在卷做空间核对和并发容量预留，接收中仍处理真实`ENOSPC`；远端大小提示不可信，实际manifest和落盘字节必须受限。预算按磁盘情况自动计算，具体默认值、并发预留释放和异常边界写入ADR及测试。

空间不足时先回收安全对象；仍不足则拒绝或取消新的复制并清理其未发布残留，不删除当前剪贴板或其他活动任务文件。已经收到的正式文件、发送源、历史记录及用户保存的副本不归此清理器管理。

删除范围仅限当前profile下程序能证明所有权的缓存对象；使用约束根目录与平台安全API，防止符号链接、reparse point、路径替换、目录逃逸及清理竞态。不移动仍对系统剪贴板可见的目录。

### 5.4 验收

自动测试用假时钟/注入磁盘容量验证保护期、压力、并发、时钟跳变、删除失败与退避；覆盖当前引用、原生读取未结束、新复制和清理并发、崩溃重启、未知目录与越界攻击。必须证明“不应删除的文件仍存在且可用”，不能只断言删除函数被调用。

双平台实际验证一次复制粘贴、应用重启后有效引用保持，以及受控无引用对象的自动回收。测试只使用自有临时文件；不依赖填满真实系统盘验证空间不足。

完成条件：真实粘贴可用、可回收对象自动释放、受保护对象不误删；用户无需任何缓存管理操作。

## 6. R3 可操作诊断

- 在现有错误码/阶段上收敛用户提示，区分未发现、待配对、等待接收确认、控制连接失败、ICE失败、认证失败、磁盘不足与文件变化。
- 主视图显示简短原因和有效下一步；详情按需展开连接方法、失败阶段、版本及最近一次尝试时间。未知信息显示未知，不将服务在线当作文件连接成功。
- 重试继续沿用授权和幂等约束；成功后清除对应旧错误，不能掩盖仍存在的原生读写错误。
- 增加用户主动触发的本地诊断导出，先脱敏后写出；不含私钥、令牌、邀请码/临时分享凭证、文件正文或完整敏感路径，不自动上传。
- 将诊断边界下沉到Go，UI只展示安全DTO；复用稳定错误分类，不匹配任意日志拼接业务状态。

验收：代表性失败通过注入或已有复现证据核对原因与动作；脱敏回归用伪凭据/伪路径；用户能从具体任务到达相关诊断。无需重跑所有无关错误码。

## 7. R4 安装 升级与退出

- 沿用手动检查、下载校验、原生安装入口；不新增静默安装或无人值守更新。
- 以实际候选安装包验证Windows覆盖安装/重启和Mac应用替换/启动，保留身份、配对、设置、草稿、历史与合法恢复状态。测试安装位置和profile隔离；对必须触及的日常安装先备份并在结束后恢复。
- schema变化先备份并验证迁移；旧程序拒绝不兼容新库。回退程序与数据兼容方案分开，不能以旧备份覆盖升级后的新业务写入。
- 窗口关闭、托盘退出、菜单退出与“退出清空队列”设置行为一致。尊重用户已有偏好；活动任务如何取消或保存恢复需明确，不静默更改默认值。
- 原生确认取消时保持原任务与草稿；退出释放listener、worker、原生入口和数据库owner，不遗留第二实例。
- 验证已有Windows SendTo、Finder Services及拖放受影响路径；不把正式系统共享签名激活混入本轮必做。

验收：准确包版本/架构/hash/来源明确；一次实际覆盖升级和一次活动任务退出/重启旅程在两平台完成。无Intel或最低macOS实机时单列兼容缺项，不伪称全平台认证。

## 8. R5 一次性临时分享

### 最小产品流程

双方安装支持该能力的LinkSend并在线。发送方选择文件或目录，创建有时效的临时分享码；接收方输入码提出领取，发送方确认该接收端，接收方确认保存位置，然后通过现有认证P2P文件引擎传输。发送方可取消未领取或活动分享。

分享码只授权这一次、这份清单和这一个接收身份；不加入永久设备组，不授予自动接收或剪贴板权限，不显示组内其他成员。首版不做浏览器下载、离线存储或多人领取。

### 授权与协议

1. 先写临时ShareGrant ADR，定义控制面能力协商、状态机、token熵与摘要存储、时限、猜码限制、并发抢占及服务重启语义；采用标准随机数与成熟密码学，不自制认证协议。
2. 区分创建、待确认领取、已绑定传输、完成、撤销和过期。领取竞争原子处理；待确认领取有短期限与配额，不能让恶意占位无限锁住分享。重复合法请求幂等。
3. 绑定分享ID、双方身份/公钥、清单摘要、授权代次及有效期。接收公钥经明确临时授权进入认证检查，不关闭TLS身份验证或公钥固定。
4. 区分领取期限和已绑定任务的恢复期限。掉线恢复只允许原接收身份和原任务；源变化重新确认，不能借旧码替换文件。完成或撤销后不再授予新文件操作；完成确认丢失时只允许核对既有终态。
5. 临时授权不能通过普通成员接口访问设备组。临时任务不隐式生成长期trusted设备；再次分享需要新授权。
6. 服务只处理授权与连接协调，不保存文件正文；清单尽量通过加密P2P传递。文件正文仍不经JS、信令或第三方中继，`relay=false`。
7. 通过新增能力显式协商；旧客户端/旧服务给出明确不支持，既有配对及普通文件传输保持兼容。新增schema采用备份、事务、回读和明确降级策略。

验收必须覆盖猜码/限频、过期、重放、两人同时领取、发送方确认/拒绝、撤销与传输竞争、跨组隔离、错误公钥、源变化、服务和客户端重启、原接收方恢复、完成后再次使用、旧端拒绝及旧功能回归。

实际完成一次Windows↔Mac临时分享及一组真实跨网络分享，核对文件hash、双方终态和没有留下永久信任/权限。跨网环境缺失时该项仍未完成，不以loopback替代。
