# LinkSend 产品功能规划

日期：2026-09-12
状态：产品规划建议，尚未进入实现；不替代 SPEC、PROTOCOL 或现有发布验收要求。
规划基线：LinkSend 0.4.0，protocol V1；源码 fbfc250159ea65dbb5840d6dadb03fe4423cf868。
用户已确认：以个人多电脑互传为主，兼顾同学、同事之间的临时分享。

## 1. 产品定位与成功标准

建议定位：**让自己的几台电脑随时收发文件、文字和截图，临时给别人发一次也足够简单；大文件中断后有清楚、可靠的恢复路径。**

核心价值按顺序是：

1. 常用设备容易找到，发送入口就在当前工作位置。
2. 接收行为可预期：存到哪里、是否需要确认、重名如何处理都清楚。
3. 任务可追踪、可取消、可恢复，失败后无需重新整理发送内容。
4. 临时分享只授权本次交接，不把临时对象永久加入个人设备关系。
5. LAN 与跨网络使用同一套交互和文件完整性保证；直连失败准确说明。

当前无需引入账号平台来表达“我的设备”。它首先是用户本地对已验证设备的归类，不证明法律上的所有权，也不自动授予免确认权限。收藏、身份信任和自动接收必须是三个独立概念。

“等待另一台电脑上线”仅指发送端本地排队。发送端仍需运行、源文件仍需可读、双方需要有一段同时在线且直连可达的时间。服务器不保管正文。

以下规划中的目标均为拟议验收目标，不是已经测得的产品结果。仅访问官方文档、仓库和发布记录，没有安装对比产品或执行其真实传输、可达性、性能测试。

## 3. 三条主要用户流程

### 3.1 给自己的另一台电脑发送

用户在 Windows 文件管理器选择文件 → “发送到 LinkSend” → 小窗口显示已选内容和常用 Mac → 点击发送 → Mac 按该设备的显式接收策略处理 → 原生通知提供“在文件夹中显示”。

常用路径应避免每次进入设置、重新选保存位置或重新建立长期配对。目标离线时保留内容和目标选择，允许“等待上线”或取消。

默认路径可以是两次操作：从系统入口选择发送，再点击目标设备；这里不把操作系统右键菜单展开层级算成跨平台固定指标。首次配对和接收确认单独统计。

### 3.2 把文字、链接或截图发到另一台电脑

用户主动点击“发送剪贴板”或在发送窗口粘贴 → 查看内容预览和目标 → 点击发送 → 接收端可复制文字、打开链接或保存图片。

第一阶段只做显式发送，不持续监听剪贴板，不自动覆盖对方剪贴板，不自动打开 URL。剪贴板中的图片/文件由 Go 后端读取和传输，前端仅接收受限预览与元数据，不能把文件正文转为 Base64 走 Wails IPC。

“文字/链接原生收件体验”需要先定义受限内容类型和兼容能力。可先提供明确标注的“保存为文本文件并发送”基础方案，不能把它伪装成旧端也理解的结构化文本协议。用户在界面主动输入的短文本允许作为受限输入交给后端；网络正文始终通过认证 QUIC。

### 3.3 给别人临时发一次

发送方选择内容 → 选择“临时分享” → 生成短时单次入口 → 对方在 LinkSend 输入 → 双方确认对象与清单 → 完成后临时授权结束。

默认不加入已有成员组，不看到其他个人设备，不继承自动接收，不自动保留长期信任。分享完成后可另行选择长期配对。

一期要求双方安装 LinkSend。二维码是入口的另一种表达，桌面场景优先做可复制短码/邀请信息，不把尚无移动客户端的扫码体验作为主闭环。

当前加入码会进入成员组并自动 pin 成员，当前陌生 LAN 成功传输也会保留 pin。因此临时模式必须有独立的授权策略，不能只增加一个按钮并复用现有加入路径。

## 4. 功能优先级与最小范围

P1 为主场景核心；P2 为后续增强。复杂度是相对判断，不是工期承诺。已有能力标记为“完善”，避免重复建设。

| ID / 优先级 | 功能 | 最小可用范围 | 用户价值 / 验收方式 | 范围和依赖 |
| --- | --- | --- | --- | --- |
| F01 / P1 | 我的设备（新增组织能力） | 本地别名、固定排序、最近使用、在线状态；设备详情集中管理信任与接收权限 | 不看 IP 或长指纹也能可靠区分几台电脑；别名不影响身份校验 | 小–中；基于既有身份；取消信任/屏蔽必须覆盖 LAN 和自动接收 |
| F02 / P1 | 系统发送入口（新增） | 窗口拖放、Windows“发送到”、macOS 分享/菜单栏入口分平台交付；复用正在运行的实例 | 文件管理器可直接发起；取消后不丢已有草稿；多文件/目录有效 | 中；必须先处理单实例及启动参数；不抢占文件默认关联 |
| F03 / P1 | 后台接收与通知（完善） | 可选托盘/菜单栏常驻、最小化启动、接收与完成通知；主动传输期间可选防自动睡眠 | 关闭主窗口后行为清楚；用户可找到并退出后台进程；完成可定位文件 | 中；保留“退出应用”；自启动明确选择；原生通知不在锁屏默认展示敏感全文 |
| F04 / P1 | 发送清单与草稿（新增） | 混选文件/目录、移除项目、总大小、目标切换保留内容；准备状态可取消 | 修改清单无需重选；一边传输仍可准备下一份内容 | 中；源文件在真正发送前重验；仅存路径不等于锁定内容快照 |
| F05 / P1 | 接收保存策略（完善） | 每台设备的接收目录、空间预检、重名时“保留两份/跳过/取消”；默认不覆盖 | 同名内容不再整批失败；保存位置和处理结果明确 | 中–大；目标命名计划绑定恢复身份；跳过不能标为已传送，部分成功有独立计数 |
| F06 / P1 | 手动发送文字/链接/截图（新增） | 显式粘贴、确认目标；文字复制、链接手动打开、截图保存 | 发送少量信息无需借助聊天或临时网盘 | 中；类型、大小、能力协商、安全渲染；不默认开启连续剪贴板同步 |

| F12 / P2 | 多设备分发（新增） | 同一草稿生成多个独立目标任务；分别确认、进度、失败重试；有界并发 | 自己多台电脑或小范围同学分发不必反复选文件 | 大；依赖 F07，目标间成功独立；带宽按每份正文计，不宣称组播节流 |
| F13 / P2 | 接收方先生成入口（新增） | “临时接收”发出单任务入口，另一端选择文件发来 | 在目标电脑先准备好保存位置 | 中–大；复用 F09 的受限授权，不能扩成无限量匿名上传箱 |
| F14 / P2 | CLI 体验与自动化（完善） | 设备别名、明确的 JSON 事件和退出码、等待上线、取消/状态/重试契约 | 个人脚本可以可靠传研究结果或构建产物 | 中；明确 GUI/CLI 同 profile 的所有权，禁止并发写坏身份/任务库 |
| F15 / P2 | 精细接收选择（新增） | 文件级勾选、目录级展开、只接收部分文件；发送端看到实际选择 | 对方发一批内容时无需全收 | 大；需要双方协商子集并绑定摘要，不能只在 UI 少显示几项 |
| F16 / P2 | 大任务资源控制（新增） | 手动限速、并发上限、暂停全部、计量网络提示选项 | 传大文件不挤占视频会议或其他工作 | 中–大；先测真实负载；延续接收端已确认字节计速 |

F01–F03 是“个人电脑随时可用”的骨架，F04–F08 是完成日常交接的体验，F09 才形成真正独立的临时分享产品能力。

## 5. 信息架构

主界面保留少量一级入口，不按网络协议划分页面。

| 入口 | 默认展示 | 可展开操作 |
| --- | --- | --- |
| 发送 | 发送清单；我的常用设备；“临时分享”；附近其他设备次级展示 | 添加文件/目录、粘贴、排队、目录筛选 |
| 收件箱与任务 | 待确认、进行中、排队、可恢复；最近收到内容 | 搜索、定位、重新发送、查看完整性结果、清理记录 |
| 设备 | 我的设备/其他已信任/附近陌生设备；信任与接收状态 | 别名、固定、指定目录、自动接收、取消信任、屏蔽 |
| 设置 | 接收默认值、后台行为、启动方式、外观与快捷键 | 服务配置、接口策略与诊断放高级区域 |

设计原则：附近发现是可达证据；“我的设备”是本地归类；信任是身份授权；自动接收是独立权限。四者不能合并成一个“已连接”标记。

任务用用户可理解的阶段：准备内容、等待对方、传输、校验、已保存、需要处理。详细页再展示实际字节、重传、双方确认和连接证据。传输完成通知不能早于既定的完整性与提交成功边界。

## 6. 顶层模块与兼容边界

保留现有 Go 核心、Wails 薄绑定、Pion ICE、quic-go 和单一文件传输内核。新增能力主要落在应用编排与用户策略层：

| 产品对象 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| DeviceProfile | 本地别名、固定顺序、关系分类、接收偏好 | 不改变设备公钥，不把收藏当授权 |
| ReceivePolicy | 对谁、保存到哪里、是否确认、大小/空间/冲突策略 | 不跳过 TLS、路径与哈希校验 |
| SendDraft | 内容选择、排除预设、目标和草稿状态 | 不承诺源文件永不变化，不启动隐式后台扫描 |
| DeliveryTask | 已有 task/attempt/session/revision、恢复与执行状态 | 不重写第二套恢复逻辑 |
| TransferQueue | 持久顺序、等待条件、并发和资源预算 | 不替代 transfer 的块状态，不由 React 管理调度 |
| ShareGrant | 临时对象、本次内容、到期/撤销、消费和恢复范围 | 不加入全成员组，不泄露其他设备，不允许扩展成任意内容授权 |

必须先设计并更新规范的变化：

- **临时分享**：当前 membership 自动 pin 所有成员与新需求不同；新增仅目标任务可用的权限。短码只作入口，不通过降低证书校验获得易用性。若需要新的短码密码认证，采用经过审查的成熟方案，不能自行设计 PAKE/密码学。
- **授权消费与恢复**：首次成功消费绑定接收身份和清单；恢复授权单独绑定同一 TransferID、内容摘要和对端。已消费入口不能重新授权其他身份。到期、取消和重试各自语义写清，不把“单次”误作“失败不可恢复”。
- **接收重命名/子集**：保留原始内容 manifest，再协商目标保存计划或新的子集 manifest；计划进入恢复校验，不能随意修改已确认摘要。
- **新内容类型**：文字、链接、图片的大小限制、保存/展示行为和能力协商写入 PROTOCOL。旧端明确降级为普通文件或要求升级，不静默绕过确认。
- **后台关闭行为**：当前 macOS 最后窗口关闭会退出；常驻是可选产品行为，需同步平台测试单、退出保护和持久偏好。真实“退出”仍结束进程与监听。
- **队列与恢复**：自动开始已由用户排队的发送，仍执行接收端确认策略。应用重启后的恢复沿用当前显式确认规则；未来若允许自动断线恢复，必须另行约定授权有效期和用户暂停优先级。
- **协议版本**：产品 minor 不等于 wire 兼容。先增加可验证能力协商与混合版本测试；是否需要新协议版本由实际 wire 变化决定，不能预先承诺全部保留 V1。
- **单实例**：系统入口交给运行中的应用；CLI/GUI 共享 profile 的写入归属明确。来源路径按数据处理，不当作命令执行。

无论内容类型、入口或排队方式，正文都只经过认证的 QUIC 数据面。自动接收只改变接收决策，不改变身份、文件系统和完整性边界。

## 7. 分阶段交付建议

以下版本号只是排期标签，正式版本按实际完成范围决定；不按日期强行发布。V1 的跨 NAT 义务持续存在，任何 UI 阶段都不能据此移出范围。

| 阶段 | 目标与范围 | 进入/退出条件 |
| --- | --- | --- |
| R0 / 当前基线收口 | 修复上一轮发现的本机撤销与 LAN 权限风险、实验资源清理风险；统一文档/CI；固定源码完成跨 NAT 故障定位和物理恢复基线 | 安全关键回归通过；可运行 FAIL 有根因与跟踪；当前包与源码、证据对应；新增 UI 不挤占未完成网络验收 |
| R1 / 建议 0.5.x | 日常电脑互传：F01 我的设备、F02 窗口拖放和首个系统入口、F03 托盘/通知、F04 发送草稿、F08 历史快捷操作、F10 基础诊断；F06 可先交付明确的文本文件发送 | Windows/Mac 实际完成“从文件管理器发起→按策略接收→通知定位”；退出/自启动选择可撤销；原有暂停恢复不回归 |
| R2 / 建议 0.6.x | 可管理的交接：F05 目的目录/保留两份，F06 文字链接截图完整体验，F07 顺序队列/等待上线，F11 可见目录预设；扩展另一平台的系统入口 | 草稿/队列重启可读；等待不占数据连接；源变化准确提示；不同保存名仍正确恢复；计数与实际文件一致 |
| R3 / 建议 0.7.x | 临时分享：F09 独立 ShareGrant、一对一入口，F13 接收方先发起；具备余量再加 F12 多设备分发和 F15 选择接收 | 旧端兼容负例、一次消费、过期/撤销/重放、无成员组泄露、失败恢复、完成不落长期 pin；真实跨网全流程可复现 |
| R4 / 稳定版候选 | 收敛常用网络、长期运行、安装更新数据兼容、全部原生关键操作；F14/F16 按真实需求追加 | 全部 V1 必需项按 SPEC 验收；可达范围明示；无数据损坏/越权；发布包与同 SHA 证据一致；签名、公证状态如实披露 |

如果 R0 网络失败尚未定位，可独立完成设计稿、入口原型和非网络元数据工作；不得以新功能数量替代已约定的网络验收。

建议每阶段只选一个主要用户旅程验收，避免把全部功能都塞进一个 minor。对应测试要覆盖真实客户端与原生入口，不能只依靠 UI mock。

## 8. 量化目标与观测

以下为候选验收方案，首轮建立基线后调整。默认本地测量，不引入强制联网遥测。

| 关注点 | 建议衡量办法 | 防止误读 |
| --- | --- | --- |
| 自己设备发送便利性 | 从系统发送入口到选定目标开始发送，一次连续流程；统计点击数和实际耗时 | 初次配对、用户接收确认时间单列，不虚构全平台统一点击数 |
| 连接可靠性 | 每个明确支持的物理 LAN 组合做 100 次连续短文件传输，记录失败阶段和成功率；跨网按实际拓扑分别统计 | 100 次无失败也不证明所有 LAN/NAT 均可靠 |
| 小内容延迟 | 文字、小文件分别记录准备、连接、传输、校验、提交的 p50/p95，双方用户等待单列 | 不用平均值掩盖长尾，不预先承诺固定毫秒数 |
| 大任务表现 | 固定大文件及大量小文件，记录吞吐、CPU、峰值内存、磁盘与后台等待资源 | 与原生 QUIC 基线和完整文件路径分别比较 |
| 队列可靠性 | 新增、排序、取消、离线等待、过期、源文件变化、进程退出后恢复逐项检查 | 等待上线不算已发送，完整重发不算缺块续传 |
| 接收与恢复 | 重名/磁盘不足/强杀/部分提交/接收已提交但发送未确认，核对哈希及唯一字节/重传/提交数 | 跳过与部分完成明确展示，已存在文件不得被误覆盖 |
| 临时分享安全 | 不加入永久成员、不泄露其他设备；过期/撤销无效；重复消费只允许绑定身份的幂等路径 | 短码并非身份本身，临时成功也不默认授予下一次权限 |
| 后台体验 | 空闲长时间运行后的内存/句柄/连接数、通知、睡眠唤醒和主动退出 | 托盘图标存在不代表后台接收和恢复均有效 |

## 9. 后续评估、暂不纳入近期实现

| 候选方向 | 有吸引力的地方 | 暂缓原因 / 重新评估触发条件 |
| --- | --- | --- |
| 手机客户端 | 随手拍照、截图传电脑，扩大日常覆盖 | 当前平台范围不含移动；需要新客户端、后台与权限设计。桌面主旅程稳定且用户需求明确后评估 |
| 浏览器免安装接收 | 临时分享阻力更低 | 浏览器无法直接沿用现有桌面身份与任意 QUIC 通道；WebRTC/HTTP 不是现有路径。必须先做独立可行性与协议决策 |
| 自动持续剪贴板同步 | 更接近无缝多设备工作 | 默认隐私预期和平台后台权限复杂；先验证显式发送的使用频率 |
| 文件夹自动同步 | 多电脑工程目录长期一致 | 更新/删除传播、冲突、版本保留是新的产品语义；Syncthing 已提供成熟专项能力 |
| 远程浏览/取文件、命令和控制 | 不必走到另一台电脑 | 扩大授权与攻击面；可先研究用户预选的只读共享目录，不能默认开放整个磁盘 |
| 云端暂存、下载链接、中继 | 减少同时在线要求或提高部分跨网成功率 | 与当前正文路径/relay=false约束冲突；只能作为后续明确修改范围的设计，不能成为暗中降级 |
| 全班/多人文件收集房间 | 方便活动资料收集 | 身份、配额、命名、并发和滥用处理更复杂；先完成一对一临时交接 |
| 自动更新 | 降低版本碎片 | 当前明确排除；先改善版本展示、兼容提示和手动下载入口，再独立评估签名与回滚链 |
