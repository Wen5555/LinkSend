# ADR0015：复制文件与大文件居中进度

状态：已随[0.6.2](../RELEASE-v0.6.2.md)发布。日期：2026-10-19。用户明确要求补齐复制文件和图片，并要求大文件复制时在屏幕中央显示“正在复制”及进度条；少量文字、图片不弹窗。32MiB阈值是本轮实现选择。

## 兼容与授权

沿用认证ICE/QUIC会话及V1文件引擎。新增独立`clipboard_files_v1`能力；只有双方显式声明，才允许files租约、文件预约和新文件流前缀。旧端仍只收到text/link/image租约，普通文件流与原剪贴板行为保持。新增files的send/receive权限独立默认关闭，桌面以“同步复制的文件”单独取得同意。不会用总开关或旧六项授权推断文件授权。

任务库11→12沿用既有精确备份、事务和回读迁移流程，保留旧权限行，扩大kind约束以容纳files；不自动插入或开启files授权。旧程序拒绝高版本任务库；回退时使用迁移前备份，不让旧程序改新库。

## 文件复制路径

1. Windows原生读取CF_HDROP，Mac原生读取file URL，最多128个根路径/64KiB元数据；不自动把普通路径文字视作文件，不删除源文件，不传播“剪切”操作。路径只在Go/native中使用。
2. 系统复制先推进原有唯一状态owner。具备新能力与双向files授权的健康会话，在原10秒lease内接收files事件，正文仅含随机TransferID、根数量和大小提示，不含绝对源路径或文件正文。
3. 接收端验证旧有身份、权限revision、代次、origin、顺序、digest和OS generation，在lease过期前预约一次文件复制。预约最多24小时，仅用于后续文件准备与传输；不延长text/link/image或未获准旧事件。新复制、暂停、撤权、连接变化或取消使预约失效。
4. files事件获`file_ready`确认后，发送端才准备manifest。新双向流使用有界`LSCF01\0\0`前缀及预约绑定，随后完整复用V1文件帧、BLAKE3、安全路径、确认与进程共享文件速率预算。每方向文件body最多两路。
5. 接收落于profile中独占、新建的`clipboard-files/<TransferID>`目录；完成完整性验证及确认后，再次检查预约、当前授权、permission revision、系统generation和取消状态，才写入本机接收路径到系统剪贴板。远端绝对路径不能进入接收方剪贴板。
6. 文件复制为临时复制会话，应用重启不补发旧复制；完成缓存保留以供系统粘贴，源文件保持。中断不把部分文件写入剪贴板。缓存管理和跨重启行为必须在交付中明确。

## 进度交互

仅大文件复制新建440×240居中置顶进度窗，显示“正在复制”。准备阶段为不确定进度，传输阶段按真实确认/校验字节计算百分比，可取消；失败提供重新复制提示。小文件和已有文字/链接/图片通道不打开此窗。窗口只接收状态、数量和进度，不接收文件正文。

## 验收要求

认证QUIC的无文件先行、文件复制落盘/本机路径、长于lease的预约、新复制/撤权/暂停/取消优先、旧端能力不足、异常前缀/长度/ID与路径、schema备份迁移、原文件协议兼容，以及Windows/Mac原生文件条目和不同像素的图片双向测试。浏览器截图只证明界面，不代替系统粘贴。本地与物理Win↔Mac候选已通过，正式包来源/CI与发布状态单列。
