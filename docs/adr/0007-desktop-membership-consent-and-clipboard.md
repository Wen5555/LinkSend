# ADR 0007：成员代际、独立 LAN 同意与自动剪贴板边界

日期：2026-09-13。状态：**语义已由总控复审接受**（11c44df，E0-safeio-close-v1）。具体API/schema/wire和实现、兼容测试仍待E1/E4；当前产品仍为 M5/V1，不代表E0整体完成。
关联：U2/U3/U4、E1–E4；不得以本文代替协议/安全兼容测试或原生验收。

## 当前缺口

`Control.Join` 的 `joinedDevice` 拒绝 revoked 身份，现有新邀请码不能重配被删设备。
`Revoke` 将权限读取与 UPDATE 分开且仍要求 Admin；移除 Admin 条件本身不足以解决互撤竞态。
邀请码仅关联 inviter ID/组，没有 inviter 当前组/成员代际检查。`Devices` 将 Nearby 合并到 Online，存在本地记录时隐去服务错误。
现有本机 denied_peers 屏障必须保留，不能用列表过滤或删除 pin 代替撤销。

## 关系与授权作用范围

设备 ID 继续由长期 Ed25519 公钥决定。增加服务端成员 incarnation（随机不可复用标识），每次离组后重新加入均生成新 incarnation；同组幂等加入不变。
设备组有单调 membership_revision；成员加入、离开和撤销在一个数据库写事务中更新成员与版本。
组是授权范围，界面不引入账号/管理员；普通成员可对当前同组成员进行添加/删除，不能操作别组，不能通过“删除自身”退出。

本机文件免确认、剪贴板发送/接收/类型授权与显示偏好分开存储。授权记录绑定 peer ID、公钥、关系范围和双方 incarnation/本地 grant generation。
成员同步只恢复有效配对关系，绝不自动恢复免确认或剪贴板权限。同名不同身份不继承授权。
明确区分“从组删除”（本提案）和现有“仅本机屏蔽”（持续生效，需本机显式解除）。历史与收到的文件不属于授权记录，不随删除清理。

## 配对码与首台初始化

新增经设备签名、限流、幂等的独立空组初始化操作；只允许无当前有效成员关系的身份，不能匿名接管已有组。服务部署 bootstrap 与日常配对分离。
动态码仍短时、单次、仅存摘要。邀请码绑定 inviter ID、组 ID、inviter incarnation、创建时版本及有效期。
生成码与消费码均在事务内读取最新 inviter；消费时 inviter 已撤销/离组/换 incarnation 则拒绝。
已消费码同身份重试仅返回原事务结果，且原成员 incarnation 仍有效；绝不重授被撤销 incarnation。fresh code 同组幂等只消费码，不提升权限。

跨组切换必须显式确认。请求携 expected current group/incarnation 和目标组邀请；验证、旧组离开、目标组加入及两个组的 revision 更新在同一事务完成，失败不产生半切换。
旧身份私钥、文件与历史保留；所有旧组自动授权失效，旧组邀请码不能把已退出关系复活。
被删身份通过新的有效码重新加入才产生新 incarnation；新关系是新的授权事件。旧快照/旧请求/旧邀请码不能产生该事件。

## 删除与同步事务

1. 本机先持久化带 request ID、目标 incarnation、已见 revision 的删除意图/拒绝屏障，同时推进该 peer 的本机授权 generation，使删除前的**全部**组关系与独立 LAN grant（包括 provisional grant）失效；原子关闭文件免确认、剪贴板与重试资格。失败则不报告已删除。
2. 再取消目标任务流、关闭相应连接和停止重试；保存文件、历史与可恢复元数据。恢复必须重新授权。
3. 提交幂等服务端删除：事务内重新检查 actor 当前有效同组关系、目标 incarnation 和请求唯一键，再变更成员与组版本。互撤竞态以提交次序线性化，已被撤销 actor 不能完成迟到删除。
4. 服务不可用时本机拒绝立即生效，明确“组变更待同步”。持久 outbox 在重启后重试同一请求。版本/目标 incarnation 冲突不得盲删后来重新加入的设备，应报告需重新确认。
5. 在线成员收到失效通知后先持久授权状态再关闭权限；离线成员重连先完整同步版本再恢复新建连接/发送。旧快照小于本机已见版本时拒绝。

所有通道先检查 peer 级拒绝屏障和当前本机授权 generation，再检查具体组/LAN grant；不能在组 grant 失效后自动回落删除前的 LAN grant。既有控制会话、数据流、排队事件和迟到确认都绑定创建时的 generation，在接受/派发/剪贴板落板前重新核对。收到服务端组撤销的成员也须持久推进目标的本机授权 generation，不能留下旧 LAN 旁路。

撤销标记不能从旧 `.previous` 或迁移备份自动复原。组删除对应的拒绝只可由**可验证的新入组 incarnation 与更新版本**解除；该事件只建立新的组配对 grant，不能恢复旧 LAN grant、文件免确认或剪贴板权限。重新取得 LAN 关系须完成新的独立同意事务。仅本机屏蔽不被新入组事件解除。
该授权区分已获语义确认；具体 UI 文案在 E1 实现时按同一语义审查。

## 旧端安全拒绝

建议引入独立 `membership_v2` 控制能力与版本化 API/信令授权字段；文件 manifest/block/receive_plan/content 帧继续使用既有结构。
升级后的组不能给不理解 incarnation/revision 的旧客户端返回可用授权。旧端得到明确 VERSION_INCOMPATIBLE/升级要求，不能继续通过 /v1 Join/Devices/WSS 绕过撤销。
新客户端面对旧服务明确要求服务升级；不得自动降级到无代际授权。数据会话建立前双方核对同一关系 grant 与双方代际，单有旧 pin 不够。
具体线编码、域分隔签名字段、API 路由、错误码与迁移 schema 在 E1 协议补丁中冻结，并增加旧端/跨组/重放/旧快照负例。
服务迁移要求备份可读验证；应用新 schema 拒绝旧端写入；回滚在隔离副本中执行，不能用旧数据库覆盖新业务写入。

## 独立 LAN 配对同意

签名发现仅提供候选身份/地址；双方 mTLS 仍必须验证公钥与会话目标。添加不依赖先传完一个文件。
请求绑定双方 ID/公钥、request ID、随机 nonce、短有效期（建议 60 秒）和本机 grant generation；一次确认只能授权该目标/请求。
双方并发发起按双方 ID 和请求键确定单一事务；拒绝/超时/取消不留下有效 pin、服务器成员或免确认。仅存去重/拒绝元数据不算配对。
确认后双方先持久 provisional grant，再交换绑定 transcript 的 commit/ack；只有持久互认 grant 才显示已配对并允许文件连接。丢失 ack 可幂等查询完成，不将未知结果解释成成功。
严格原子跨设备提交在断网下不可保证；允许单侧“等待完成确认”，但此状态不得发送正文或宣称双方完成。provisional grant 有界过期清理。

本地 LAN 关系与服务器组是不同事实。服务不可用可完成本地互认，跨网络状态保持待完成；不得伪造服务器入组。
有服务时，由同意方请求仅绑定已同意 peer 身份/组/双方 grant 的短期服务凭证。目标已经属于其他组时必须走上述显式切换，不静默合并。
凭证过期后不离线积攒无限加入权；恢复后重新核验双方 grant 和当前组，必要时重新确认。

## 统一设备目录与连接事实

按 DeviceID 合并一行，但保存独立的关系状态、服务 health、WSS authenticated、membership synced revision、LAN 公告时间/来源、控制验证结果和实际 QUIC 状态。
每个地址保留接口、本地源地址、族、网络 generation、过期与验证结果。看见公告不等于控制连接或文件可达，WSS 正常不等于对端在线。
组播、广播、受限单播/记忆地址和 WSS 分别降级；socket 所有权和错误重建有界。健康 QUIC 不依赖一次发现刷新或信令重连。
复用官方 LocalSend 的接口/地址/失败隔离思路，不改用 HTTP 文件传输、不扫描子网。IPv6/mDNS 在 E1-04 依据一手来源及实测单列选择，不在 E0 假定已实现。

## 剪贴板权限、时效与冲突

总开关默认关闭；每设备、方向和类型明确 opt-in，双方均授权后才启用。文件免确认或旧内容草稿不能迁移成剪贴板授权。
Windows AddClipboardFormatListener、macOS changeCount 由原生/Go 采集和写入。正文不经 JS/WSS，不写日志，临时快照在完成/过期后释放。旧端不支持时明确停止，不能伪装成普通文件自动接收。
事件身份为 origin DeviceID + origin incarnation + origin boot generation + origin_sequence；类型和正文 digest 与该身份绑定。origin_sequence 是本机真实复制事件的单调计数，仅用于本来源去重/顺序，不兼作 Lamport clock。相同文本的真实新复制仍递增 sequence 并产生新事件。

### 可证明的传输新鲜度

采用**接收方预先签发的短期 freshness lease**，初始有效期建议10秒。lease 含不可预测 nonce/ID，绑定当前已认证 QUIC 会话、双方身份/incarnation、本机授权 generation、发送方向和允许类型；接收方在有界内存表保存签发时的单调时间与不可延长的 deadline。线上不要求两端解释相同的绝对墙钟或单调时间值。

发送方只有在收到 lease 后产生的真实本机复制才可用于该 lease；采集时立即固定 lease ID、OS clipboard generation、origin_sequence 和本地单调截止时间。没有 lease 的复制不排队等新 lease，也不能在取得新 lease 后重新采集旧剪贴板当新事件。连接/授权初始化先交换 lease，再显示同步就绪；续期提前进行，但仅供随后发生的新复制使用。
安装新 lease 时在原生采集 owner 内记录当时的 OS generation 基线；先前排队但尚未处理的通知不能仅凭“回调在 lease 到达后执行”变成新复制。只有基线之后实际变化的 generation 可产生该 lease 的事件；已绑定旧 lease 的事件不迁移。

这一因果顺序保证 lease 签发早于被其授权的事件产生：接收方按自身 deadline 拒绝时，不依赖对端墙钟，也不让滞留事件从到达时重新获得10秒。发送前还须检查事件未过本地期限、仍是当前 OS generation、lease/会话/授权仍匹配。该机制限制正确实现所发事件的传输陈旧性，不宣称能证明恶意已授权发送者提供的正文刚刚来自其真实剪贴板。
有效性推理：同一接收方单调时间轴上的 lease 签发点为L、事件实际产生点为E、落板检查点为C；因果约束给出L≤E，接受要求C<L+TTL，故C−E<TTL。线上无需传输或估算E。lease传输慢时可保守拒绝本来较新的事件，但不会让过期事件获得新寿命。

接收方在首帧/offer、正文接收期间、完整解码后和最终落板门闩内均检查**同一个原始 lease deadline**。第一帧、整图或重传流滞留超过期限时拒绝/取消，回收本事件暂存；不能从首帧到达、开始解码或重传时重新起算。旧事件禁止改绑新 lease、重发为新事件或通过快照恢复补发。

lease 到期只停止对应事件，不关闭健康文件流或整个复用会话。接收方可以在同一长连接中签发新 lease，每方向最多保留两个未到期 lease；新 lease 不延长旧 lease/旧事件寿命。重连、睡眠/锁屏、授权撤销和双方代际变化清空 lease 表；旧 session 的 nonce 即使数值未过旧期限也无效。解锁后建立新 lease，只处理后续新复制。

macOS 单调时间源需包含睡眠时长（例如 mach_continuous_time 的正确换算）；Windows 同样使用包含系统挂起时长的单调来源，并配合唤醒时清空 lease。不能直接假定某语言计时器在系统睡眠时仍推进。具体原生时钟/线格式在E4核实，测试必须模拟或实测挂起跨越deadline。

### 并发排序与落板门闩

离线不积攒；恢复等待新复制；锁屏暂停采集/写入且解锁不补发；快速复制只保留最新尚未提交事件，并核对读取前后 OS clipboard generation。
写入远端事件产生的本地通知与事件 origin/digest/OS generation 关联并抑制转发，不能只凭正文 hash 永久去重（用户可能主动再次复制同文字）。

Lamport clock 独立表示逻辑因果顺序：本机新复制先将 clock 加一；观察通过身份/代际/lease/去重检查的远端事件时更新为 max(local, received)+1；重复/无效事件不推进。计数溢出明确停止该代际并重新建立会话，不回绕。远端事件的排序键保留发送时的 (lamport, origin ID, origin boot generation, origin_sequence)，不改写为接收方更新后的 clock；同类型/同正文也按事件身份区分。

接收解码可并行，但原生剪贴板提交只有一个 owner。每个候选保存开始时的 OS clipboard generation 和应用提交 revision；最终在**同一串行落板门闩**内重验当前OS generation/revision、锁屏/暂停、授权generation、lease期限、来源去重高水位与候选排序，再执行原生写入并登记新OS generation/提交revision/回环抑制信息。授权撤销与该门闩协调：撤销持久提交之前已线性化的写入可完成，提交之后的候选一律不能落板。

本机新复制优先于在其前已开始接收的远端候选：OS generation变化立即使那些候选失效。若另一远端已经提交，其他并行候选即使都通过过早先的检查，也因应用revision改变而丢弃；不得在旧检查结果上继续写入。对同一revision尚未提交的候选按上述稳定键选胜者；不能为等待可能还未到达的事件无限延迟。已提交键的高水位拒绝随后抵达的更旧事件；晚到的新候选仍必须满足全部新鲜度与本机generation检查。

门闩防止应用内两个解码任务的检查/写入竞态，不自动解决其他应用在OS级检查与写入之间复制的竞态。Windows需在同一OpenClipboard所有权期间检查和写入；macOS没有据此已核实的通用跨进程CAS承诺，须在E4原生验证最窄写入窗口、changeCount复核及冲突反馈，明确实际能力边界，不能将应用锁冒充全系统原子性。
顺序规则须用三设备并发测试冻结；不宣称异步网络可提供跨设备全局同时性。暂定文本/链接64KiB，PNG编码32MiB/40MP上限沿用已校验内容约束，原生解码内存另测。

## 所有权和会话调度

每 profile 唯一 Go owner；先测量 historyDB 频繁开关和已有队列 store 的成本，再收敛连接生命周期。身份授权仍只有一份真实来源。
入队、授权、接收计划、恢复检查点和终态承诺必须等待必要提交；UI 进度可有界合并，不削弱 fsync、commit intent 和文件身份验证。
按同一已认证对端/双方 grant generation 复用 QUIC 会话；每文件任务与剪贴板事件使用独立受限流。取消任务只关对应流，身份撤销/网络失效/退出关闭相应会话。
建议每对端最多1个文件任务和1个剪贴板事件，文件块与小事件采用带预算的公平调度；文本/图片限速、每连接与全局上限均固定，不能无限开 goroutine 或饿死文件。
先用连续小文件/大文件+剪贴板/取消和持久化失败测试确认收益，再开放更多并发。
