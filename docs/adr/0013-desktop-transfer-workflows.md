# ADR 0013：统一传输队列、文件打开与本地删除

日期：2026-10-18。状态：0.6.0 后源码修复，已随[0.6.1](../RELEASE-v0.6.1.md)发布。验证与平台边界见[实施记录](../evidence/DESKTOP-060-WORKFLOW-FIXES.md)。

## 文件与记录

记录页展开文件清单并滚动到清单，再分别提供“打开文件”和“打开所在文件夹”。JS只提交task/file ID；Go根据持久接收计划或发送任务的SourcePaths解析路径。接收文件仍须完成双方确认；未选条目、缺失/大小变化的文件、符号链接、非法相对路径被拒绝。发送目录按原始选择根匹配，不重新遍历/哈希整个目录来定位一个条目。

Windows通过ShellExecute调用文件关联、Explorer定位；macOS使用绝对路径`/usr/bin/open`及`-R`。接收不会自动打开文件，只有明确点击才调用系统关联。

## 删除与黑名单

桌面“删除设备”改为本地ForgetPeer，立即撤去pin、免确认、剪贴板权限、设备偏好和旧代任务，取消旧会话；不调用服务端成员删除，也不保留“已删除设备”目录。发现同一身份时可以作为未配对设备重新请求明确同意。独立“加入黑名单”继续持久拒绝连接；移出黑名单不恢复旧权限。CLI/管理层已有Revoke及离线成员撤销outbox含义保持。

trust schema3新增可选`denied_peers[].forgotten`。这是防止后台成员快照恢复同一授权的内部标记，不是黑名单：新配对入口允许通过，但AuthorizationGeneration仍要求有效pin；旧授权代次、旧LAN provisional和旧任务不能继续。新LAN明确同意可用新代次提交；成功输入配对码加入后，只清该认证结果内的forgotten标记，LocalBlock和待同步撤销保持。旧schema3程序忽略字段时会保守地将其作为拒绝，不会获得额外权限。旧outbox不自动转换为普通删除。

## 队列与退出

传输页一个列表合并发送队列与收发任务，task_id相同的发送只显示一次。运行、等待、暂停、失败及完成放在同一处；保留批次取消与确认继续；速度与进度来自Go真实计数。新增条目进入末页，发送成功滚动到队列。已信任设备的新增接收显示导航计数，进入传输页清零，重连attempt不重复计数。

“清除已完成记录”隐藏完成任务；“清除所有任务”确认后先取消本次快照内未完成收发，再隐藏记录。取消尚未收尾时仍显示取消状态，同时新到项目保留。使用既有SQLite metadata表的`transfer_view/queue/<id>`及`transfer_view/task/<id>`，后者绑定attempt；历史、源文件和接收文件不删除。新attempt从历史恢复时重新显示。

偏好格式仍为1，新增`retain_transfer_queue`，缺省false。通用设置“退出后自动清空传输队列”对应其反值，按原分类CAS保存。默认退出取消未完成任务并清空本页；启动补清异常退出遗留，旧记录留在“记录”。原生退出弹窗与设置一致，自动清空开启时明确取消退出；关闭后沿用原保存/重启确认行为。该设置只管理桌面，不改变CLI恢复策略。

## 自动剪贴板

主开关与逐设备权限继续默认关闭。设置页增加逐设备双向开关，明确设置send/receive × text/link/image，沿用逐项revision CAS；部分失败后重新读取实际权限，不声称原子成功。两端均须开启主开关与对应设备权限。

原生窗口runtime-ready后再设置Windows owner并注册监听；启动失败由既有定时owner重试。Windows监听包含注册PNG格式；文字读取对短暂占用最多等待750ms，同代次、可取消，新复制淘汰旧读取。

ResetClipboard恢复后立即唤醒各连接已有lease owner。原7秒周期晚于3秒空闲关闭，导致连接在续期前关闭；真实QUIC回归先复现失败，再验证立即交换lease和新文本交付。暂停、锁屏、离线不补发旧正文，授权代次/修订、回环抑制与独立正文预算保持。

文件及剪贴板wire版本、身份校验、正文不经过JS/信令、`relay=false`保持。
