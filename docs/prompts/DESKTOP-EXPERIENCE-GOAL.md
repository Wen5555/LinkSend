## 2. 分工与上下文

- 总控：`gpt-6-astra`，默认 `medium`，复杂决策/审查才临时 `high`。执行任务：**`gpt-5.6-sol`，`medium`**。在可用任务设置中实际配置；文字不代表已切换，不支持设置时说明一次限制。
- 复用一个独立执行任务及工作树，获准创建的任务确实不存在才新建。已有任务支持改模型则原地改；不支持时一次交接简短续接索引到指定模型，原执行者停止写入后再接手，不循环尝试切换或双写。
- **总控负责目标、依赖、技术决定和关键审查；执行任务承担实现及全部常规重复工作**：资料定位、状态核对、诊断、测试、失败修复、构建、远程操作、证据整理、TODO/文档、Git/PR 和 CI 跟踪。总控不再做一遍。
- 执行任务独占产品源码、测试、文档和 Git 写入。总控如需补充证据，给出一个明确问题交其查证；只有会改变验收结论的疑点才亲自复测。
- 两者遵守适用 AGENTS；执行者改代码前读 SPEC、PROGRESS、方案相关章节。总控首次读目标与验收章节、当前 TODO；恢复只读简短交接和当前差异，需要判断具体问题时再展开代码/契约。
- 完整日志、实验历史和详细上下文留在执行任务及现有证据文件；总控只保留当前目标、已接受决定、未解阻塞、当前/下一批、提交与证据路径。不要反复复制方案或整段历史。
- 复用一个 TODO 和简短进度记录；按阶段追加必要证据，不为每次尝试、回执或监督检查另写报告。查找用 rg，独立读取批量执行，只返回相关片段。

## 3. 连续执行、排队与引导

一次给出阶段目标、范围、完成条件和已知依赖，允许执行者内部拆解并自主完成实现→检查→修复→文档→阶段同步。常规修复、局部重试、已授权操作不返回主控索要下一步；避免微批次和仅为确认收悉的往返。

- **排队**：用于下一批或不紧急补充，通常只保留一个清晰的后续批次，写明启动条件。总控审查或 CI 等待期间，执行者可推进已授权且不依赖待定结果的工作；依赖项未通过就不提前进入。
- **引导/steer**：当前方向错误、关键缺陷、误报完成或反复无效试错时立即使用，写清证据和修正条件，并明确替代哪条旧指令。不能用普通排队冒充即时纠偏。
- 正常派发不要求“收到”回执，从后续实际行为判断落实；关键纠偏仅在无法确认送达或仍继续偏离时补查一次。没有有效引导入口且继续执行会破坏当前成果时，暂停执行者后一次交接。
- 每个主要阶段或较大可验收闭环，执行者自行完成检查、提交、工作分支推送、同一 draft PR 更新、远端 SHA 与 CI 核实，随后**一次交付**。这是候选交付，不代替总控验收。
- 总控集中审查提交差异、验收映射和关键逻辑；普通已通过检查直接复用有来源的结果，不例行重跑测试、拉取同份日志或再次查询相同远端状态。发现实质矛盾、源码/环境变化才重验受影响部分。
- 阻断项一次合并引导修复，执行者自行修好、检查并同步，只返回变更与剩余问题；总控只审相关增量。非阻断建议进入后续 TODO，不把措辞、样式偏好或假设性问题变成返工门槛。
- 总控验收后自动启用下一批，不等用户确认，不要求执行者再发送一遍验收回执。

阶段交接通常不超过 8 行：批次与结果、commit/PR/CI、必要检查及证据路径、真实缺项、下一步。无阻塞不逐个转发内部失败；原始失败证据仍保留。

## 4. 检查范围与故障处理

检查按改动影响选择，缓存有效结果；源码、依赖、构建配置或相关环境改变后才重跑受影响项。Go 两模块独立，含 `GOWORK=off`；阶段及最终补齐方案/仓库要求的测试、vet/race、前端与原生构建，不能因省 token 跳过要求或关闭 CI。普通文案、文档、可逆样式调整不新增机械测试或触发无关平台全量构建。

已接受设计无新证据不重审；只处理真实缺陷、明确验收要求及当前改动引入的风险。不要主动扩成通用安全审计、兼容框架或灾备工程；只读和普通可逆本地操作不套生产变更清单，也不反复确认已有授权。

原型验证技术路线即可，不打磨成第二套产品。相同失败无新证据就改变假设或诊断方法；不要原样反复构建/注册/卸载。执行者先处理常规故障，涉及路线选择时携带错误、已试方法和推荐下一步一次交总控。

真正依赖才阻塞后续：单个平台/签名卡住可继续独立平台、网络、配对或存储；E0 全绿不是全项目开工条件。网络原型未证明前不扩张 UI，可先修网络内核；提前推进不豁免最终缺项。需要用户证书、系统操作或新增权限时，先准备具体可审阅材料，再一次说明最小动作，同时继续独立工作。

任务通信故障只作一次轻量核查，复用可靠入口；不开发 UI 自动化、CLI 接管或会话日志轮询框架，不抢锁、不另起写入者。缺少可靠入口就说明实际限制，不假称已送达或已监督。

## 6. 监督、阶段与结束

总控优先用已知任务 ID/hostId/cursor 的 `wait_threads` 获取简短增量，仅交付、阻塞或需要决策时展开。无独立工作就有界等待，不紧密轮询日志/Git，不生成无变化汇报。5 分钟 heartbeat 仅作空闲/中断后备，总控活跃时不重复监督或派单；有实质变化、完成、失败或需用户动作才通知。

复用实际未完成项：先由执行者核实并同步已有 E0 提交；补 E0 必要证据 → E1 设备/配对/LAN → E2 接收/设置/布局/旧入口迁移 → E3 两平台正式共享 → E4 存储/会话/调度与剪贴板 → E5 准确候选包联合验收。真实依赖允许调整顺序，不漏项。

同目标 Goal 已存在则复用，否则获执行授权后创建，不自行设置 token 预算。全部七项及平台/网络/同步交付完成后才 complete；外部阻塞按 Goal 的连续阻塞规则处理，不能把实现困难当外部阻塞。用户停止时停止派发、妥善停止本任务作业并暂停 heartbeat，简短交接，不把未完成目标标成完成。
