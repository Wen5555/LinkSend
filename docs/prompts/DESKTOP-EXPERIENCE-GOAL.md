## 4. TODO、子代理和集成纪律

使用现有 TODO 作为唯一工作清单。每项保留稳定 ID、对应 U1–U7、依赖、验收条件与证据位置，状态简明区分待做、进行中、待验证、已验证或外部阻塞。源码实现、自动测试、原生/网络验证和 GitHub 同步分别记录，不能用一个勾混为完成。

先判断当前最短完成路径，再选下一批有明确结果的工作。通常沿用 E0→E1→E2→E3→E4→E5：
- E0：复用已有基线与原型，补必要的网络和原生共享证据。
- E1：设备删除/配对状态、LAN 发现和网络恢复。
- E2：一次接收、设置分类、布局及旧内容入口迁移。
- E3：两平台正式共享与小面板、文件授权和安装生命周期。
- E4：必要的存储/会话/调度改进、自动剪贴板同步。
- E5：准确候选包联合验收、升级兼容与最终同步。

根据实际依赖调整顺序：网络原型未证明时先修网络，不扩张 UI；单个签名或平台阻塞不阻止其他独立内核/平台工作。已验证成果不因阶段名称重跑，提前推进也不豁免最后的缺项。

使用子代理时：
1. 分派具体、可验收且有边界的工作，例如独立模块实现、另一平台验证、协议负例检查或对已完成 diff 的审查。能自己快速完成的局部修改直接做。
2. 每项明确允许修改的文件/目录、共享接口、测试、不能触碰的资源和交付格式。主代理与子代理不同时编辑相同文件；依赖共享接口先约定。
3. 主代理保留一条有用的本地工作线。只有没有独立工作时才等待，遵守工具并发上限，不为了用满槽位制造子任务。
4. 不允许多个代理同时操作同一台机器的安装、剪贴板、测试 profile、数据库迁移或部署。分配明确的平台/资源使用者，完成后释放；不要为此另造通用调度系统。
5. 子代理默认不 commit/push、不改其他人的文件、不自行部署生产；阶段集成、Git、数据库迁移和生产变更由主代理统一执行。需要委派某个远程操作时明确唯一执行者及资源范围。
6. 子代理返回改动摘要、实际检查结果、证据与剩余问题，通常控制在 8 行以内；完整日志留在文件，不反复复制上下文。
7. 主代理检查改动和关键证据，整合后运行必要的跨模块检查。子代理写的“完成”不自动算验收；没有新变化或实质疑点也不机械重复全套测试。
8. 对授权、协议、持久化和系统共享等高风险改动，可用另一子代理做有范围的审查；要求报告可验证的问题，不进行无限轮假设性审计。
9. 在当前任务内使用 collaboration 子代理，不默认创建用户侧新对话。复用有帮助的现有子代理；不要让子代理无限递归拆分。

## 5. 检查、故障与资源使用

检查按改动影响选择并复用有效结果；源码、依赖、构建配置或相关环境变化后重跑受影响项。阶段/最终补齐仓库要求：Go 根模块与 apps/desktop 独立检查，含 GOWORK=off；适用的 test/vet/race/build、前端 typecheck/lint/tests/build 及原生构建。低风险文案和样式不新增机械测试或触发无关平台全量构建。

相同失败没有新证据时改变假设或诊断方法，不原样反复构建、安装或注册。先提出最可能原因，用最小实验区分，记录结果后修复；原型只验证路线，不扩成第二套产品。已有正确设计无新证据不重做，不顺便迁移技术栈。

遵循以下边界：
- 保留设备身份验证、完整性、安全落盘和恢复。协议/授权/schema 变更更新契约，并验证兼容及相关负例。
- 使用已核实的 Pion ICE/quic-go API，不自造简化 ICE；relay=false；文件和剪贴板正文不经信令、JS IPC 或第三方中继。
- Windows↔Mac 按发现、配对、建连、接收、落盘分别取证。localhost、公网主机和同桥容器不自动算双 NAT。
- 系统共享注册成功、窗口出现不等于文件授权与后台交接成功；真实菜单和准确包必须验证。
- 覆盖方案中的冲突、目录、源变化、取消、暂停、进程异常、重启、网络/睡眠恢复与剪贴板并发/回环等行为。
- 最终证据绑定源码 SHA、包 hash、平台/架构、网络条件和实际步骤；旧包结果不能直接套到新包，NOT RUN 不能写成 PASS。
- 不为节省协调开销削减必要检查，也不靠重复无变化的测试拖延交付。只读和普通可逆操作不套完整生产流程。

证书、系统人工授权、主机条件等真实缺项出现时，先把独立工作做完，并准备具体可审阅结果，再一次说明用户需要做的最小一步。不要提前询问已经授权的动作；不要通过关闭验证、伪造测试或将系统共享替换成普通菜单规避阻塞。
