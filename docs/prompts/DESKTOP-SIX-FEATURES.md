## 总提示词

```text
请在当前 LinkSend 仓库中落实六项桌面能力，让“个人多电脑之间随手互传”成为完整、可靠的用户流程。请先审计现状并给出简短执行顺序，然后完成实现、适当验证、修复和文档更新；不要停留在概念规划、占位界面或模拟后端。

一、读取上下文并锁定范围

阅读仓库及适用祖先 AGENTS.md、docs/SPEC.md、docs/PROGRESS.md、docs/ARCHITECTURE.md、docs/PROTOCOL.md、docs/SECURITY.md、docs/TESTING.md、docs/ACCEPTANCE.md、两份既有 ADR，以及：
- docs/DESKTOP-SIX-FEATURES-PLAN.md：本轮功能契约、技术决策和验收依据。
- docs/PRODUCT-PLAN.md：只用于产品背景，不自动扩展到其中其他功能。

本轮编号与用户所选功能严格对应：
S01 我的设备；S02 系统发送入口；S03 托盘常驻与原生通知；
S04 显式文字/链接/剪贴板截图；S05 接收清单与保存决策；
S06 本地队列与可操作收件箱。
S02 所需草稿、S05 所需 ReceivePlan、S06 所需 schema/调度属于必要实现。

记录 branch、HEAD、工作树和当前工具版本。仓库可能已有用户未提交的规划、测试产物和其他代码，保留原样。若有 CodeGraph 索引按项目规则先用；没有索引不自行建立。联网核实官方能力时使用 web-access，涉及 SSH 时使用 codex-ssh-manager，桌面视觉工作使用 frontend-skill 的 Apps 指南。

二、采用现代、相互兼容的技术栈

保留两份 Go module；根模块包含共享核心，桌面模块承载 Wails/系统依赖。
保留 Pion ICE、quic-go、Ed25519/TLS 1.3、BLAKE3 和 SQLite；文件正文不得经 WSS、HTTP 上传/下载、JavaScript IPC 或第三方中继。relay=false，跨 NAT 仍是既有产品范围。

以 2026-09-12 官方资料核实的下列组合为升级目标，并在执行时重新核对：
- Go 1.27.1。
- Node 24.21.0 LTS、pnpm 12.4.1。
- React/React DOM 19.3.0。
- TypeScript 6.0.3、typescript-eslint 8.70.0。
- Vite 8.3.0、@vitejs/plugin-react 6.1.1、Vitest 5.0.0。
- TanStack Query 5.102.8 管理类型化查询/快照缓存。
- 按实际需要增加 Radix 控件及 TanStack Virtual 3.14.12，不整套堆入状态管理、组件和动效依赖。
- Wails 当前为 v3.0.0-beta.18；较新 beta.20 仍是预发布。先独立核实平台能力和迁移变化，再决定是否同步升级 CLI/Go/runtime/build assets。

这些是候选目标，不是已经在本仓库通过验证的组合。TypeScript 7.0.2 虽更新，但当前 typescript-eslint 的 TS peer 为 >=4.8.4 <6.1.0，且 TS 7 不兼容旧编译器 API；不要使用 --force/忽略 peer 的方式升级。若未来兼容关系已变化，以实际官方证据更新决策。

按工具链组合逐步升级并留清楚回滚边界。遇到可修复兼容问题应修复；确有上游不兼容时保留精确的已验证版本并记录证据，不以框架重写或禁用检查解决。Go 1.27 要特别回归 JSON、规范签名、manifest、未知字段和持久历史兼容性。依赖锁定精确版本，只有一个 pnpm lockfile。
中国大陆环境优先利用已配置网络、缓存及可达源；必要镜像与官方版本、完整性对照，不永久改全局代理/源。

React 负责交互与展示，Go 持有任务、草稿持久状态、授权、队列和文件生命周期。使用 Wails 类型化绑定/事件、revision 门控、事件丢失后的快照重取；不能把任务状态机或块调度复制进前端。局部表单状态优先 React hooks，避免同时引入 Redux/Zustand/XState 管同一数据。
Vite升级必须显式检查最低WebView2/WKWebView目标，不能静默提高最低macOS；绑定生成输出独立执行类型检查。Query的撤销/接受/取消/入队等命令不做未经幂等设计的自动重试，不能由乐观UI宣布数据已提交。

三、逐项完成用户行为

S01 我的设备
- 本地别名、固定与排序、最近真实使用、专属接收目录。
- 别名/收藏/“我的设备”标签不改变公钥信任和自动接收。
- 设备权限集中可见；撤销/屏蔽同时影响 LAN、WSS、新排队任务和恢复，不能删掉 pin 后马上被自动重新 pin。
- 远端改名、DHCP、重启不导致设备重复或权限串用。进行中任务保持原接收计划。

S02 系统发送入口
- 文件/目录拖放，发送清单增删去重，切换目标保留草稿。
- 基础必交付为窗口拖放、Windows用户级SendTo和macOS Finder Services；平台Share Target/Share Extension、托盘图标拖入单列可选扩展，不把服务菜单冒充系统分享扩展。
- 使用经固定版本源码确认的 Wails 单实例与二次启动参数，按 profile 隔离；同 profile 一个写入者。
- 处理 Args、WorkingDir、Unicode、空格、多文件、重复激活；系统入口创建可见草稿，不自动发送到上次目标。
- 系统临时文件URL/授权在入队前取得可靠访问权或存成用户所选内容的受控快照；多选超过argv系统上限准确提示，不截断后假装全部加入。
- 文件正文不从 WebView File API 读取，不以 Base64 传到 Go。

S03 托盘与通知
- 可选关闭窗口继续接收、托盘/菜单栏显示、明确“退出应用”；自启动默认不启用。
- 隐藏窗口保留正常接收；真正退出停止新请求/派发，保存任务并有界结束资源。退出时保留恢复状态，不把所有任务都强行取消。
- 通知在真实接收请求和既定成功/失败终态触发，按 task/revision 去重；点击后用 task ID 打开界面/定位文件。
- 通知无权限时回退到应用内，不影响传输结果；锁屏不默认暴露内容全文。
- 区分“暂停队列派发”与“暂停当前传输”；睡眠唤醒后重建必要连接，不重复订阅或发送。
- 原生防自动睡眠仅覆盖活跃传输，并在暂停/退出时释放。

S04 文字、链接、剪贴板截图
- 用户显式输入/粘贴/点击读取剪贴板，预览目标后发送；不做连续监听或自动同步。
- beta.18 clipboard 只提供文本，图片/剪贴板文件列表走薄原生 adapter，禁止杜撰图片 API。
- Go/原生层创建限额、不可变的内容快照；排队后剪贴板改变不影响已选内容。执行规划中的文本/编码大小/像素上限及失败清理。
- 文本类型与链接/图片通过可协商的认证 QUIC 内容路径传送。可先提供明确的文本文件基础方案，但最终要完成复制文字、手动打开链接、保存图片的完整体验。
- 旧端不支持新类型时明确解释并由用户选择普通文件方式或升级；不静默降级身份/确认。
- 用户主动输入的短文本可作为受限表单 DTO；文件/图片正文不经 JS IPC。缩略图需要受限本地展示设计，不能把原图 Base64 当预览捷径。
- 收到文字不自动覆盖剪贴板，URL 不自动打开，不执行命令；未知 scheme 仅作文本。
- 历史默认保留任务摘要，正文保存/清理规则单独可见。

S05 接收决策
- 接收前显示内容、清单、目录、总量、剩余空间和冲突；可选择文件/目录子集，默认不覆盖。
- 重名支持保留两份、跳过、取消；选择与保存计划在正文请求前明确。
- 保留 original manifest，ReceivePlan 绑定选择集合/内容摘要/目标相对路径；绝对接收目录不发给对端。
- skip 不计入 verified/sent/committed；全部跳过有明确无内容结果；部分接收的完成语义是协商子集完成，不能冒充原始全量完成。
- no-replace 原子提交覆盖 TOCTOU；名称碰撞有界处理。计划和 commit record 持久化，恢复不得改变命名后重复提交。
- 空间预检不是落盘保证；ENOSPC、目录失效、权限变化仍有稳定结果。
- 旧端缺少子集能力时明确告知，不通过少请求块绕过完整校验。

S06 队列与收件箱
- Go 持久队列，首期全局活跃传输并发 1；当前忙时也能可靠加入下一项。
- 入队幂等、事务调序/取消、等待对端、到期/需处理状态；离线任务不阻塞其他可运行任务。
- 等待复用现有 presence/发现与抖动退避，不为每项常驻 WSS/ICE/QUIC 资源。
- 发送端必须运行且源仍可用；不称离线云投递。排队后源变化重新准备并提示。
- 重启后队列可见，未完成/待发项先要求确认继续；沿用 task/attempt/session/revision 和已验证缺块恢复，不复制第二套恢复引擎。
- 历史按设备/日期/状态/名称查询，后端分页；提供在文件夹中显示、重新发送、恢复和清理记录。
- 重新发送是新逻辑任务，恢复沿用原任务；文件已移动如实显示。
- 清理记录不删除接收文件；清理暂存仅清无任务引用、由本应用创建的孤立内容，保留可恢复任务所需数据。

四、实现顺序与设计交付

按详细规划 M0–M6 推进：
M0 核实基线、工具链和原生能力，修复与这六项直接相关的安全/生命周期前置缺陷；
M1 类型化快照、设备策略、草稿/持久队列基础；
M2 单实例与系统入口；
M3 后台生命周期和通知；
M4 接收计划/冲突/子集与恢复；
M5 文字链接截图；
M6 完整收件箱、跨功能联调和包级验证。

先用真实源码决定最小新增模块，不凭目录图创建空包。新增协议、schema、文件保存计划和平台入口要有简洁 ADR，选择执行时未占用的编号。同步 SPEC、PROTOCOL、ARCHITECTURE、SECURITY、TESTING 和当前进度，使规则与最终实现一致。
规范中旧 Wails 2 描述应按现有 Wails 3 实现与本轮授权纠正，不能据此回迁。

网络与文件完整性要求持续有效。UI 工作不把既有 NAT FAIL 改成 PASS，也不取消跨 NAT 范围。没有真实 Mac/双 NAT 环境时，继续完成本地和独立工作，留出可运行复测入口并准确记录缺口；不要用一个外部环境缺口阻塞所有六项的源码推进。

桌面使用克制、清晰的现有视觉系统：发送工作区、设备列表、任务/收件箱、设置；一个主强调色，明确空态/禁用/错误/焦点。真实长文件名、中文、键盘、系统缩放、深浅色和 reduced-motion 都可用。拆分过大的 App.tsx，新增代码使用实际生成的类型和语义组件，不扩大 lint 豁免。

五、验证与交付

对本轮变化执行有意义的验证：
- 根模块 gofmt、go mod verify、go test、go test -race、go vet、go build；根与桌面分别验证 GOWORK=off。
- 桌面独立 mod verify/test/vet/build；前端 frozen install、typecheck、lint、组件/状态测试和 build。
- 必要时增加测试工具，但不为静态样式写镜像实现的测试；安全、协议、文件提交、调度和恢复需要故障回归。
- Wails bindings 重新生成并检查；前端 build 和 Go embed/production build 串行。
- PowerShell 每个原生命令检查退出码；不能前面测试失败、最后 build 成功就报告整体成功。
- Windows/macOS 原生文件入口、托盘、通知、退出、安装/卸载分别验证；浏览器自动化不当原生验收。
- 真实 QUIC 测试覆盖撤销、队列重复派发、暂停/取消迟到事件、选择接收、保留两份、磁盘失败、源变化、强杀恢复和双边完成。
- 混合版本验证新内容/子集能力和稳定错误；编译通过不能代替兼容性。
- LAN、跨 NAT、网络切换、睡眠、物理双机恢复仅对实际运行的场景报告结果；不承诺任意网络100%可达。
- 用独立profile和目录，保留用户文件。需要使用NAT脚本时先保证只清理本次创建的实验资源。
- 默认不自动 push/部署/发布；本轮用户已明确授权逐阶段推送、部署和测试预发布，按精确commit及事务回滚执行。仍不修改主机防火墙/路由/代理，也不为原生点击绕过系统权限。

最终交付可运行的本地实现、升级后锁定的依赖、迁移和回滚说明、原生构建产物及六项验收表。
每项列出“已实现/自动化结果/真实原生或网络证据/未运行及原因”，附实际命令与退出码。记录源码SHA、dirty状态、产品/协议版本和包哈希。不要把占位函数、假事件、纯mock界面、旧包截图或未执行测试描述成完成。

每阶段完成后更新进度并继续下一项；只有完成全部可执行工作或遇到确需外部输入的依赖时才结束。正常实现选择自行判断，不反复请求已授权的本地操作确认。
```

## 六条分项提示词

用于逐个迭代。它们引用同一份详细规划，保留总提示词中的数据路径、兼容、用户文件和验证要求。执行者应先检查依赖阶段是否已完成，补齐本项必要前置能力，避免重复实现。

### S01 我的设备

```text
请落实 LinkSend 的 S01“我的设备”。先阅读 docs/DESKTOP-SIX-FEATURES-PLAN.md 的技术路线、S01、模块边界及统一完成标准，并遵循 docs/prompts/DESKTOP-SIX-FEATURES.md 总提示词的公共约束。

交付本地别名、固定排序、最近真实使用、专属接收目录和清楚的接收权限。收藏/我的设备分类不能自动授予信任或免确认。解决本机撤销后 LAN 仍可能沿用 pin/auto_accept 的问题，避免自动发现或成员同步把已屏蔽设备重新授权。元数据迁移、重启恢复和不同身份同名负例都要验证。
完成真实后端、类型化绑定和设备界面，记录实现、测试和未验证平台；不要扩展成账号平台或临时分享。
```

### S02 系统发送入口

```text
请落实 LinkSend 的 S02“系统发送入口与草稿”。阅读 docs/DESKTOP-SIX-FEATURES-PLAN.md 的 S02、单实例/草稿/队列依赖及公共约束。

让窗口拖放、Windows SendTo、macOS Finder Services 把文件/目录交给同一发送草稿；应用未启动、隐藏或正在传输时都不丢内容。使用固定版本确认过的 Wails 单实例和二次启动数据；按 profile 隔离，正确处理 WorkingDir、中文空格、多文件和重复激活。系统入口只准备内容，用户选择目标后再发送。
Windows Share Target、macOS .appex、托盘图标拖入都是单独平台能力，不用假菜单/浏览器截图冒充。新增平台代码留在桌面模块；注册/卸载不改默认关联，不触碰用户文件。完成相应原生验证并明确签名/平台限制。
```

### S03 托盘、后台与通知

```text
请落实 LinkSend 的 S03“托盘常驻、后台接收与原生通知”。阅读 docs/DESKTOP-SIX-FEATURES-PLAN.md 的 S03 和统一生命周期/验证要求。

提供用户可选的关闭窗口继续接收、唤回主窗口、打开收件箱、暂停队列派发和真正退出；自启动不默认开启。后台继续接收与退出时保留恢复状态都走真实Go服务。通知按task/终态revision去重，点击用不透明任务ID定位；权限拒绝不影响传输。区分窗口关闭/程序退出/暂停派发/暂停传输，解除所有事件订阅和防睡眠资源。
在真实Windows/Mac窗口验证隐藏、再激活、通知、活跃任务退出与睡眠唤醒；缺平台时准确标记，不把浏览器测试算原生证据。
```

### S04 文字、链接与截图

```text
请落实 LinkSend 的 S04“显式文字、链接、剪贴板截图发送”。阅读 docs/DESKTOP-SIX-FEATURES-PLAN.md 的 S04、内容边界与兼容要求。

交付主动粘贴/读取→内容确认与目标选择→认证QUIC传输→接收端复制文字、手动打开链接或保存图片。beta.18图片剪贴板没有现成统一API，使用薄原生adapter并在Go层生成限额、不可变快照；文件/图片正文不能走JS IPC。不要连续监听剪贴板、自动覆盖接收端剪贴板或自动打开URL。
设计content能力协商、大小/像素限制、内容摘要、快照清理和旧端明确降级。临时文本文件方案可作开发中间步骤，不能替代最终三种内容完整体验。验证图片解码上限、排队后剪贴板变化、危险scheme、新旧端和取消清理。
```

### S05 接收清单与保存决策
