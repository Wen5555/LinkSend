围绕“可用性、可信度、现代桌面体验”检查整个项目，修复不合理、过时、容易误导用户或缺少边界的实现。优先保证真实工作流：启动、配置、配对、核验设备、发送、接收确认、进度、失败诊断和恢复。保留下文当时要求的 Go 核心与桌面模块边界；当前桌面已迁移到 Wails 3。文件字节只能走经身份认证和加密的 P2P QUIC 数据面，不能经过信令、JavaScript IPC 或第三方中继。

## 配对测试约定

为了降低本地 UI/e2e 验证成本，在显式 loopback 开发配置 `configs/server.dev.toml` 中提供固定配对码 `orion123`。该配对码必须满足以下边界：

- 仅在 `allow_insecure_loopback = true` 且开发服务绑定 loopback 时启用；生产配置和公网服务拒绝该配置。
- 使用常量时间比较；服务端仍要求注册请求的 Ed25519 签名和设备身份。
- 不替换生产高熵、短时、一次性的邀请令牌，不写入日志，不进入生产文档或默认公网配置。
- 配对码只用于反复测试，后续删除时应只需移除开发配置和对应测试分支。
- 前端在设备/配对页明确标注“仅测试使用”，支持一键复制，并提示生产服务不接受该码。

## 可用性与产品行为

检查并改进：

- 启动后是否能看懂当前状态、服务地址、成员资格、设备在线状态和下一步动作。
- 在线、已加入设备组、已验证指纹、已建立直连必须分别展示，不能混成一个“在线”状态。
- 发送端只显示等待确认；接收端显示发送者、内容摘要、数量、目标目录和接受/拒绝按钮。
- 错误按阶段、稳定错误码和可操作建议展示，不能把原始 HTTP/栈信息直接丢给用户。
- 任务状态、取消、失败重试、完成后打开目录、轮询防重叠和窗口退出保护要保持一致。
- 所有不可信名称按文本渲染；键盘焦点、禁用态、空态、加载态、失败态和 `prefers-reduced-motion` 都要可用。

## 前端视觉要求

采用 Apple 风格的排版、分组、圆角关系和材质层次，但不要复制品牌资产：

- 以简洁、现代、克制为视觉主线；使用系统字体或最多两种字体、一个主强调色。
- 用留白、字号层级、分组表面、细分隔线和半透明材质建立层次，减少厚重边框、阴影和无意义卡片。
- 传输、设备、设置/诊断三个区域保持清晰的工作流；标题先说明用户要做什么，文案短而具体。
- 控件圆角、间距、按钮层级统一；主操作只有一个明显强调色。
- 首屏先展示真实工作面和状态，不做营销式 hero、统计卡片拼贴或无意义渐变。
- 至少检查桌面宽屏和 720px 以下窄屏：导航折叠、表单不溢出、任务操作可点击、重要文本不被裁切。
- 动效只用于页面进入、状态/布局变化和按钮反馈；尊重减少动效设置。

## 工程边界

不要重写 Pion ICE、quic-go、TLS、身份、文件完整性、路径安全或协议格式；不要为了“看起来能用”改成 HTTP 上传、WebRTC、TCP 或信令中转。协议变更要更新文档和兼容/安全测试。所有新增配置必须说明默认值、来源和生产风险。每个里程碑记录修改文件、实际命令、结果、未运行项和下一步。

## 交付与验证

交付前至少完成：`gofmt`、`git diff --check`、根模块测试/vet、桌面模块 `GOWORK=off` 测试/build/vet、前端 typecheck/lint/test/build；若改动涉及行为，再运行对应集成测试。若能运行桌面预览，检查传输、设备、设置三页和窄屏截图；否则说明阻塞原因。最终报告按“已实现、已在当前环境验证、未运行/外部阻塞、后续工作”分开，不能把静态检查写成真实网络验收。
